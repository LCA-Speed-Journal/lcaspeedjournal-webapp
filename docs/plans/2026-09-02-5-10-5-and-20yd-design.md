# 5-10-5 Agility and 20yd Dash — Design

**Date:** 2026-09-02  
**Status:** Validated  
**Scope:** Add `5-10-5_Agility` and `20yd_Dash` as Speed Journal intake metrics, and include both on the sport-defaults norms matrix.

---

## 1. Decisions and success criteria

Locked in brainstorming (2026-09-02):

| Topic | Decision |
|--------|----------|
| 5-10-5 entry | **A:** one time → `Athlete-Comfort`; two times (`L\|R`) → `L`, `R`, plus `Average` |
| 5-10-5 sport test | **A:** `Average` and `Athlete-Comfort` are the same primary. L/R are extras |
| 20yd live mph | **B:** mirror 40yd — `10-20yd` ranks in mph; other splits show mph under time; full `0-20yd` stays seconds |
| Sport defaults | Both keys on the Hugo-group matrix, independently of 40yd |
| Weight room | No card mapping in this change |

**Success criteria**

- Coach can log `5-10-5_Agility` as `4.52` or `4.48|4.56` without a session component setting.
- Two-sided days store L, R, and Average; one-sided days store Athlete-Comfort only. No `L-R` % row.
- Sport default / testing-day / PRs / overall leaderboard treat Average and Athlete-Comfort as the 5-10-5 result.
- `20yd_Dash` with default splits emits `0-5yd`, `0-10yd`, `0-20yd`, `5-10yd`, `10-20yd`. Overall is `0-20yd`.
- Live board: `10-20yd` is mph-primary; other 20yd splits show mph secondary; `0-20yd` is seconds only.
- Each Hugo group can assign a population to 5-10-5 and to 20yd separately (e.g. basketball uses 20yd, football uses 40yd).

**Out of scope**

- Weight-room card mapping for 20yd or 5-10-5
- Side labels on `5-0-5_Agility` / `5-0-10_Agility`
- Deriving 20yd rows from a 40yd trial
- Session `day_components` UI

## 2. Registry and parsing

Add two keys to `src/lib/metrics.json`.

### `5-10-5_Agility`

- Category Speed, subcategory Agility
- Input/display units `s`, no conversion
- Not ISO `paired_components` (those require a matching label count and add `L-R` %)
- Dedicated parse: one or two numeric values

| Input | Rows |
|--------|------|
| `4.52` | `Athlete-Comfort` |
| `4.48\|4.56` | `L`, `R`, `Average` (mean of the two) |

Order is positional: first value is L, second is R. Reject 0 values, 3+ values, and non-numeric parts.

Entry hint: `e.g. 4.52` (Athlete-Comfort) or `4.48|4.56` (L then R). No side dropdown.

### `20yd_Dash`

- Category Speed, subcategory MaxV (same family as `40yd_Dash`)
- `input_structure: "cumulative"`, `interval_unit: "yd"`, `default_splits: [5, 5, 10]`
- Existing cumulative parser emits named yard windows. Defaults:

`0-5yd`, `0-10yd`, `0-20yd`, `5-10yd`, `10-20yd`

Session split overrides work like 40yd (`10` for a 10yd-only mark; `5,5,10` for a full 20). Value count must match the split count.

Session setup: add a 20yd yards note next to the existing 40yd split note.

### Live mph (20yd only)

Reuse the 40yd mph helpers, parameterized by metric + fly split + full-run split:

- `10-20yd` ranks/displays mph (analogous to 40yd `20-40yd`)
- Other 20yd splits show mph under time
- `0-20yd` stays seconds-primary, no mph secondary

## 3. Sport norms and zone matching

Add both keys to `NORMS_DEFAULTS_METRIC_KEYS`. Each Hugo group can map a population to 5-10-5 and to 20yd independently.

### 5-10-5 primary

The sport standard is one lower-is-better time. Default cuts use an empty/overall component.

Zone attach, testing-day, PRs, flags, team overview, historical, and leaderboard “overall” treat **`Average` and `Athlete-Comfort` as the same primary**. Helper: a result row is primary when its component is `Average` or `Athlete-Comfort` (and when the requested component is empty/overall).

L and R stay named extras: optional cuts and testing-day picker entries, not the sport test.

Cuts editor for 5-10-5: component picker with **Overall** (default), **L**, **R**. Overall matches Average or Athlete-Comfort at read time.

Testing-day named components: list Athlete-Comfort / Average / L / R when those rows exist that day; fallback Overall + L + R.

### 20yd primary

Same pattern as 40yd:

- `getPrimaryComponent("20yd_Dash")` → `0-20yd` (sum of default splits)
- `defaultCutsComponent("20yd_Dash")` → `0-20yd`
- Empty component on a 20yd query resolves to `0-20yd`
- Cuts editor split dropdown: `0-5yd`, `0-10yd`, `0-20yd`, `5-10yd`, `10-20yd`
- Testing-day named-component fallback includes that set (as 40yd already does)

## 4. Surfaces and helpers

**Shared helpers** (keep 40yd behavior, extend rather than fork blindly):

- Primary-result matching for 5-10-5 (`Average` \| `Athlete-Comfort`)
- Yard-dash mph readout keyed by metric (`40yd_Dash` fly `20-40yd` / full `0-40yd`; `20yd_Dash` fly `10-20yd` / full `0-20yd`)
- Named component lists for cuts + testing-day fallbacks

**Touch existing call sites** that special-case `40yd_Dash` or `getPrimaryComponent`: editor metrics, NormsEditor component picker, testing-day component resolution, live leaderboard mph, PRs/flags/team-overview/historical filters.

**Do not** add 20yd/5-10-5 mapping on weight-room cards or scan review.

---

## 5. Testing

TDD. Parser and helper tests first; then editor/testing-day/live-readout.

- 5-10-5: one value → Athlete-Comfort; two values → L, R, Average; reject three values
- 20yd default splits emit the five named windows; `getPrimaryComponent` is `0-20yd`
- `isPrimaryResult` (or equivalent) matches Average and Athlete-Comfort, not L/R
- mph primary only on `20yd_Dash` + `10-20yd`; mph secondary on other 20yd splits except `0-20yd`
- `NORMS_DEFAULTS_METRIC_KEYS` includes both keys
- `defaultCutsComponent("20yd_Dash")` is `0-20yd`; 5-10-5 overall is empty
